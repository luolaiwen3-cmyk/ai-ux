# InsightUX 产品设计与验收规范

## 1. 产品目标

InsightUX 是面向 UX 研究员的单租户私有化测试平台。研究员创建测试任务并向被试发送匿名链接；被试授权后完成任务，系统同步采集操作事件和面部特征；研究员随后回放会话、触发 AI 诊断并导出可分享报告。

比赛版本必须形成一条真实闭环：

```text
创建任务 → 发布链接 → 被试同意与校准 → 完成测试
  → 会话入库 → 回放与指标分析 → AI 诊断 → 报告导出/分享
```

页面存在或展示静态示例数据不视为功能完成。只有数据在上述链路中真实产生、关联、保存并可重新读取，才算通过验收。

## 2. 用户与权限

### 被试

- 使用不可预测的任务 Token 匿名进入，不需要账号。
- 只能读取当前发布任务的公开说明并创建自己的会话。
- 只能向自己的会话追加采集数据和提交任务结果。
- 可以随时退出，并删除尚未提交的采集数据。

### 分析人员

- 使用部署环境提供的管理员密码登录。
- 可以创建、编辑、发布、暂停任务。
- 可以查看所有任务、会话、诊断和报告。
- 管理端接口必须在服务端校验登录态，不能只隐藏前端入口。

## 3. 核心领域模型

### Task

| 字段 | 含义 |
|---|---|
| `id` | 稳定 UUID |
| `token` | 被试访问用随机 Token |
| `name` | 任务名称 |
| `description` | 被试可见说明 |
| `scenario` | 当前可执行场景，比赛版为 `checkout-coupon` |
| `steps` | 有序任务步骤 |
| `status` | `draft` / `active` / `paused` |
| `createdAt` / `updatedAt` | 审计时间 |

### Session

| 字段 | 含义 |
|---|---|
| `id` | 稳定 UUID |
| `taskId` | 所属任务 |
| `participantCode` | 展示用匿名编号 |
| `status` | `created` / `recording` / `completed` / `abandoned` |
| `consentAt` | 同意时间 |
| `startedAt` / `completedAt` | 测试时间 |
| `couponDecision` | `applied` / `declined` / `none` |
| `rrwebEvents` | 行为回放事件 |
| `faceFrames` | 降采样后的关键点、情绪和可选缩略图 |
| `metrics` | 服务端或可信客户端生成的聚合指标 |

### Diagnosis / Report

| 字段 | 含义 |
|---|---|
| `sessionId` | 对应会话 |
| `status` | `pending` / `completed` / `failed` |
| `provider` / `model` | 真实模型或明确标注的本地规则引擎 |
| `severity` | `P0` / `P1` / `P2` / `NONE` |
| `confidence` | 0–1，必须可复现，禁止随机生成 |
| `summary` / `rootCause` | 结论与根因 |
| `evidence` | 带时间点和数据来源的证据 |
| `recommendations` | 可执行优化建议 |
| `shareToken` | 只读报告分享 Token |

## 4. 系统架构

比赛版本采用单进程私有部署：

- React + Vite 提供被试端和分析端页面。
- Node HTTP 服务同时提供 JSON API 与生产静态资源。
- SQLite 保存任务、会话、诊断和登录会话。
- rrweb 与 MediaPipe 在浏览器采集；数据通过分批 API 上传。
- AI 服务只从服务端调用，密钥不进入浏览器。
- 未配置 AI 密钥时使用确定性的规则诊断，并在界面和报告中明确标记为“本地规则引擎”，不得冒充 Qwen。

本地存储只允许保存短期录制缓冲和界面偏好，服务端数据库是业务数据的唯一真相来源。

## 5. 功能验收标准

### P1 入口与知情同意

- Token 无效、任务暂停或未发布时不能开始。
- 摄像头检测与页面展示一致；比赛版不采集麦克风，因此不显示虚假麦克风检测。
- 面部检测必须使用 MediaPipe 的真实结果，失败时允许“仅行为数据”降级，并明确提示。
- 隐私说明必须准确描述保存的数据和保留方式。

### P2 校准

- 只有连续检测到面部后才显示校准成功。
- 降级模式由用户确认，不得自动伪造检测成功。
- 校准完成后创建唯一会话并进入对应 `/task/:sessionId`。

### P3 测试任务

- 任务页校验当前会话状态。
- 记录实际优惠券选择、点击与完成时间。
- 完成后上传行为和面部数据，状态变为 `completed`。
- 离开页面时尽力保存缓冲；主动退出时删除未提交数据。

### A1 任务管理

- 创建、编辑、发布、暂停均持久化。
- 只为 `active` 任务提供可访问链接。
- 暂不支持的场景不能作为可发布选项展示。

### A2 会话列表

- 支持状态、严重程度、是否含面部数据筛选，以及时间排序。
- 数据来自服务端并支持手动刷新。
- 任务名称、参与者编号、时长和诊断状态真实关联。

### A3 深度分析

- 只加载路由 ID 对应的会话，不得回退到其他会话数据。
- 时间轴使用实际录制时长，rrweb、面部帧与压力曲线同一时间原点。
- 行为指标、情绪峰值和最终选择来自当前会话。

### A4 报告

- 报告使用已保存的当前会话诊断，不含写死日期和指标。
- 打印样式可生成 PDF；分享链接通过不可预测 Token 只读访问。
- 未生成诊断时显示明确空状态。

### A5 仪表盘

- 所有指标由真实会话和诊断聚合。
- 普通视图和 Admin 视图均无运行时错误。
- 不展示无法从系统状态证明的 API、存储容量或健康状态。

## 6. 非功能要求

- `npm run build`、单元测试和关键流程集成测试全部通过。
- 所有写接口校验请求体、资源状态和权限。
- 对采集数据设置大小上限，日志不得输出人脸图像或完整 rrweb 内容。
- `.env.example` 记录全部配置但不包含真实密钥。
- README 包含开发、测试、生产启动、数据目录、AI 配置和隐私说明。
- 每个功能独立提交，提交前必须运行与该功能相关的验证。

## 7. 明确不在比赛版范围

- SaaS 多租户与计费。
- 团队成员分级权限和外部 OAuth。
- 注册流程、SaaS 仪表盘等第二测试场景。
- 原始连续摄像头视频保存。
- 宣称医疗级、心理学级情绪识别准确率。
