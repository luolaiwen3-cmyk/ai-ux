# InsightUX 系统分析文档

## 一、比赛版定位

**InsightUX** 是一个 AI 驱动的 UX 智能诊断平台。通过在被试自然操作界面时采集多模态数据（行为轨迹、面部表情、认知压力），结合 Qwen3-VL 大模型推理，自动识别 UX 缺陷并生成诊断报告。

**比赛版范围**：单租户本机部署，2 角色，8 模块。数据由 FastAPI 写入 SQLite 和本地压缩文件，不依赖外部数据库服务。

---

## 二、商业叙事（文档层面，不额外开发）

> InsightUX 采用「私有化优先、SaaS 扩展」的双模式商业策略。
>
> 比赛版本聚焦私有化部署，确保企业敏感数据（用户面部图像、产品界面）不出本地；未来通过云端多租户架构，向中小企业提供轻量化订阅服务。

## 三、两角色定义

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| **测试人员** | 被试用户，通过链接匿名参与测试 | 自然完成测试任务，不打扰 |
| **UX 分析人员** | 研究员 / 产品经理，含 Admin 权限 | 管理任务、分析会话、产出报告、查看全局数据 |

---

## 四、8 模块清单

### 角色 1：测试人员（3 个模块）

| # | 模块 | 说明 | 状态 |
|---|------|------|------|
| P1 | **入口页** | 测试说明、知情同意、设备检测（摄像头/麦克风权限） | ✅ 已完成 |
| P2 | **校准页** | MediaPipe 面部校准，确认面部可被捕捉 | ✅ 已完成 |
| P3 | **测试任务页** | 真实的测试页面（结算页+优惠券弹窗），被试自然操作 | ✅ 已完成 |

### 角色 2：UX 分析人员（5 个模块）

| # | 模块 | 说明 | 状态 |
|---|------|------|------|
| A1 | **任务管理** | 创建测试任务、生成测试链接、选择预设场景 | ✅ 已完成 |
| A2 | **会话列表** | 所有被试会话总览，支持筛选/排序 | ✅ 已完成 |
| A3 | **单会话深度分析** | 回放 + 多模态 + Agent 诊断（核心页面） | ✅ 已完成 |
| A4 | **报告导出** | 诊断报告持久化、打印为 PDF | ✅ 已完成 |
| A5 | **仪表盘** | 普通视图 + Admin 全局视图 + 系统设置入口 | ✅ 已完成 |

## 五、信息架构（IA）

```
InsightUX
│
├── 🧪 测试人员端（匿名，通过 Token 链接进入）
│   ├── /join/:token        → P1 入口页（说明 + 设备检测）
│   ├── /calibrate          → P2 校准页（面部校准）
│   └── /task/:sessionId    → P3 测试任务页（核心）
│
└── 🔬 分析人员端（需登录）
    ├── /                   → A5 仪表盘（首页）
    ├── /tasks              → A1 任务管理
    ├── /sessions           → A2 会话列表
    ├── /sessions/:id       → A3 单会话深度分析（核心）
    └── /sessions/:id/report → A4 报告导出
```

## 六、用户旅程

### 6.1 测试人员旅程

```
收到测试链接 → P1 阅读说明 + 同意知情 + 设备检测
    → P2 面部校准（确认可被捕捉）
    → P3 开始任务（自然操作结算页 → 优惠券弹窗出现 → 决策犹豫 → 完成决策）
    → 任务自动结束
```

### 6.2 分析人员旅程

```
登录 → A5 仪表盘（查看今日数据概览）
    → A1 创建新任务（选择场景 → 生成链接 → 发给被试）
    → A2 查看会话列表（筛选/排序待分析会话）
    → A3 深度分析（回放操作 + 多模态数据 + 触发 Agent 诊断）
    → A4 导出报告（PDF / 分享链接）
```
